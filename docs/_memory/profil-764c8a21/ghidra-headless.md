## Konsumseiten-Regeln (Batch 32, CONFIRMED — 0 neue Laeufe)
- **Die SHARC-LESESPUR ist gratis im Log**: `-log` + konppc-Handler loggen jeden Shared-RAM-Zugriff:
  `[:konppc] ':dsp1' (020DFC) dsp_shared_ram_r_sharc: (board 0) 00000C26 = 0010` (Read-PC + Offset + Wert).
  Rollen: `020DFC`(+FB-FE) = Opcode-Fetch der Interpreter-Schleife; `020DD7`/`020DD9` = 0x56-Handler
  Payload param_1/param_2; `020D48`/`020D4A` = 0x5C/0x5D-Handler (Selektor/Bank-Index); `020223-02023A` =
  0x10-Transform-Handler (16 Worte), `02022E` = **Chained-Fetch** des naechsten Opcodes.
  ⇒ Konsumseite, Record-Segmentierung und Record-INHALT offline rekonstruierbar (0 MAME-Laeufe!).
- **Setup-Attribution**: "letzter Read-PC vor dem Textur-Tripel" = ausfuehrender Handler (Writes sind
  inline-Kopien eines Helfers). Ergebnis `-str 220`: 0x56 64,4 %, 0x5C/0x5D 27,9 %, 0x10 2,6 %,
  0x65/0x66-Handler nur 0,02 % ⇒ Textur-Record BINDET, Dreiecks-Handler SCHREIBT.
- **Setups sind keine Record-Eigenschaft**: "Emission = Setup" gilt nur bei 1 Dreieck je Record
  (statische Fruehszene, dort `act5d == Y5d` exakt). Spaetere Phasen: `C ≈ 2 Kopien/Frame`
  (Transport kalt) bzw. `act56 138 vs. V56 239` (Unterkonsum). Immer in 100-Frame-Bloecken pruefen.
- Emitter FUN_8001B0D0/FUN_8001A9A8 haben **kein** Gate (kein Culling/Untexturiert-Flag) — nur
  Opcode-Variante bei `param == 0x200`; Registrierer droppt nur Laenge 0 / Live-Modus.

## ROM-Datenarbeit (Batch 33, CONFIRMED)
- **Daten-ROM-Bytes = Datei-Offset** in `rom/build/830d01.27p.be.bin` (2 MiB):
  ROM-Offset X ↔ Ghidra `0xFFE00000+X` ↗ Alias `0xFF000000+X`. Nicht mit
  `rom/830d01.27p` (word-swapped, komprimiert) verwechseln.
- Container-Erkennung: Magic **`LZ ` = 0x4C5A2000** (LZSS) vs.
  **`FDC\0` = 0x46444300** (Methode 1, `FUN_8002B3D8`). Kopf je
  `{Magic, Pruefsumme (32-B-Summe der Ausgabe), Groesse}` + Daten ab +0xC.
  ⇒ **Vor jedem „komprimiert, Format unbekannt"-Schluss erst die Magic pruefen.**
- **Staerkster LZSS-Test = Container-Kopf** (Groesse UND Pruefsumme = zwei
  unabhaengige Kriterien); 104/104 auf einmal > jede Live-Einzelprobe, 0 MAME.
- Tabellen-Erkennung im ROM: `{u32 name_off, u32 ziel}`-Records + Stringprobe am
  Ziel (`cstr`). Basis-Offsets sind **relativ zur Block-/Tabellenbasis**, nicht
  zum ROM-Anfang.
- `read_memory`-Antwort hat `data` (Liste) UND `hex`; Tabellen 4-B-ausgerichtet lesen.
