======== 3. Probelauf: Befehl -> Stop -> Neustart ========
  Ausgangswert (absichtlich AN): True
  Telegram-Antwort: Dauerbetrieb: AUS
  SOFORT auf der Platte:        False
  nach Neustart (frisch gelesen): False
  nach STOPPEN:                 False (Zustand STOPPED, stopped=True)
  Gegenrichtung (/autonom an):  True
  Vorgabe fuer eine fehlende Datei: False (also AUS)

======== 4. Batch-Nummer nach einem Abbruch ========
  Ankerkopf im Decomp-Repo nennt: BATCH 207
  expected_batch() = Anker + 1  : 208
  Der Zustand selbst zaehlt NICHT mit (kein zweiter Zaehler):
    state['batch'] auf 999 gesetzt -> expected_batch() bleibt 208
  Folge: Wird ein Lauf abgebrochen, OHNE dass der Worker den Ankerkopf
  fortschreibt, bekommt der naechste Lauf DIESELBE Nummer; sein Review liegt
  wieder in runs/b<derselben Zahl> (die neue Fassung ueberschreibt dort
  auftrag.md/stream.jsonl - der Vorgaenger steht als stream-v1.jsonl im ZIP-Schutz).

======== Regeln ========
 * `/autonom off|on` schreibt SOFORT in den Zustand (orchestrator.handle_command).
 * Beim Laden werden fehlende Felder aus DEFAULTS ergaenzt - ein gespeichertes
   False bleibt False, ein True bleibt True. Weder Stop noch Neustart fassen es an.
 * Eine fehlende Zustandsdatei ergibt AUS (Vorgabe).
